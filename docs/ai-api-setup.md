# AI API 購買與使用說明

這份文件說明系統要用的 AI 怎麼購買、怎麼管理帳號與費用、每個 AI 角色用什麼模型，以及後端怎麼串接。
AI 角色的評分規則見 [scoring-design.md](scoring-design.md)；模型供應商的決定見 [CLAUDE.md](../CLAUDE.md)「技術棧」。

- 負責人：亭慧（AI 邏輯負責人）
- 適用對象：所有後端組員；付款與帳號管理者

> ⚠️ 價格、Console 的選項名稱與位置可能會變動，**實際購買前請以 Anthropic 官方定價頁與 Console 畫面為準**。
> 本文件的價格資料日期為 2026-10。

---

## 一、先搞懂：API 不是「一個 AI 買一個」

- 系統所有 AI 都使用 **Anthropic（Claude）**，透過 **Claude API** 呼叫。
- **一個帳號、按用量付費**：6 個 AI 角色共用同一個組織帳號，不需要每個角色分開購買。
- **沒有月費方案**：API 是預付儲值，依實際用量（token 數）扣款。
- **模型不用事先選**：一個帳號、一把金鑰就能使用所有模型；用哪個模型，是後端程式**每次呼叫時指定**的。
- ⚠️ **Claude Pro／Max 訂閱不包含 API**。那是個人在 claude.ai 聊天用的方案，API 要另外在 **Claude Console（開發者平台）** 開帳號。

---

## 二、購買步驟

1. **在 Claude Console 註冊組織帳號**（團隊共用的組織，由一位管理者建立）。
2. **綁定信用卡**（目前預計綁指導教授的信用卡）。
3. **儲值額度**：API 是預付制，先儲值再使用。
4. **關閉「自動儲值」**：Console 通常有「額度用完時自動從信用卡加值」的選項。因為綁的是教授的信用卡，**建議關掉**，避免程式出錯時自動扣款；額度用完時由管理者決定是否加值。
5. **設定花費上限**：例如儲值 100 美元、上限設 80 美元（數字僅為舉例）。用到上限時 API 會停止服務，不會繼續扣款。
6. **建立 workspace（建議）**：例如「開發測試」與「正式上線」分開，各自設定花費上限，方便看各自的用量。
7. **建立 API 金鑰**：每個 workspace 各建一把。
8. **把金鑰放進後端的 `.env`**（見第三節）。

## 三、帳號與金鑰管理規則

| 規則 | 說明 |
|---|---|
| 不共用帳號密碼 | 用 Console 的「邀請成員」功能，每個人用自己的登入加入同一個組織。誰做了什麼查得到，有人離開也只要移除他 |
| 一位管理者 | 由一位管理者（教授或 PM）負責付款、花費上限與成員權限 |
| 金鑰分開建 | 「開發測試用」與「正式上線用」各一把，各設上限。某把外流時，只要停用那一把 |
| 金鑰只放後端 `.env` | 不能放在前端、不能 commit 進 repo、不能貼到群組、不能貼給 AI（CLAUDE.md 規則） |
| 定期查看用量 | 管理者定期到 Console 看用量與剩餘額度 |

## 五、6 個 AI 角色

角色有 6 個，但實作上是 **3 種引擎、6 種用法**：回答、評分、偵測，練習和競賽各一套。

| 模式 | 角色 | 什麼時候呼叫 | 預設模型 | 呼叫方式 | system prompt 要放什麼 |
|---|---|---|---|---|---|
| 練習 | 回答 AI | 學生每送出一則 | Opus 5.5 | 串流 | 一般助手的指示；不放題目情境 |
| 練習 | 評分 AI | 回合結束（提交或要提示） | Opus 5.5 | 結構化輸出 | 4D 判斷卡、通用判斷規則、該題的適用指標與交付規格 |
| 練習 | 4D 行為偵測 AI | 回合 2 以後，每送出一則 | Opus 5.5（可評估換小模型） | 結構化輸出 | 4D 行為清單、交付規格 |
| 競賽 | 回答 AI | 學生每送出一則；出題時產生基準答案（每題 3 次） | Opus 5.5 | 串流 | 中立助手的指示；不知道題目背景 |
| 競賽 | 評分 AI | 每回合投票完成後；出題時評基準答案 | Opus 5.5 | 結構化輸出 | 4D 判斷卡、解方評分規則、答案參考庫、基準答案 |
| 競賽 | 面向偵測 AI | 每隊每 1～2 分鐘批次一次；學生提交時一次 | Opus 5.5（可評估換小模型） | 結構化輸出 | 答案參考庫的面向清單、基準答案摘要 |

各角色的完整規則見 [scoring-design.md](scoring-design.md) 第九～十一節。

## 六、多模型分工與省錢

### 可以多個模型一起用

可以，而且不用另外購買。例如評分 AI 用 Opus 5.5、偵測 AI 用 Haiku 5.5，每次呼叫時指定即可，費用依各模型單價計算。

### 換小模型之前要注意

1. **先測試再換**：小模型一次呼叫比較便宜，但判斷錯了會給學生錯的回饋，或需要重新評分，反而不划算。
   拿同一批模擬對話，大小模型各跑一次，跟人工評分比對準確度，確認夠準才換。
2. **也可以調低「思考深度」（effort）**：同一個模型可以設定思考得多深，設低一點也能省用量。
   有時候大模型用較低的思考深度，比換成小模型更準、費用差不多，值得一起測。
3. **同一個角色固定用同一個模型**：提示快取是以模型為單位，同一個工作在不同模型之間切換，快取就不能共用。

### 建議的嘗試順序

一開始**全部用 Opus 5.5**，先把功能做出來。之後依下表逐步測試：

| 角色 | 適合試小模型嗎 | 理由 |
|---|---|---|
| 練習 4D 行為偵測 AI | 最適合先試 | 只判斷「有沒有出現某行為」；不計分，判斷錯了影響小 |
| 競賽面向偵測 AI | 適合試 | 只判斷「談到哪些面向」；不計分 |
| 評分 AI（練習、競賽） | 不建議 | 直接決定學生分數與排名，準確度最重要 |
| 回答 AI（練習、競賽） | 視情況 | 回答品質影響學生能不能練到東西，要實際試用比較 |

## 七、後端怎麼串接

1. 後端用 Anthropic 官方 SDK 呼叫 Claude API（Python、TypeScript／JavaScript、Java、Go 等都有官方 SDK，依後端語言選擇）。
2. 每次呼叫指定：**模型 ID**、**該角色的 system prompt**、**對話內容**。
3. 依角色使用 API 內建的功能（都不用另外購買）：

| 功能 | 用在哪 | 為什麼 |
|---|---|---|
| 串流（streaming） | 回答 AI | 學生不用等整段寫完才看到回覆 |
| 結構化輸出（structured outputs） | 評分 AI、偵測 AI | 強制回傳固定欄位的 JSON。規格規定「評分 AI 只判斷 0／1／2，分數由後端算」，後端需要可靠地讀取 AI 的判斷 |
| 提示快取（prompt caching） | 評分 AI（以及其他 system prompt 很長、每次都一樣的角色） | 22 張判斷卡每次都一樣，開了快取，重複的部分只要付很低的費用 |

4. 金鑰從 `.env` 讀取，不寫死在程式裡。

## 八、費用怎麼估

最花錢的地方通常是：

1. **回答 AI**：次數最多（每則都呼叫），而且每次都要送整段對話歷史，越後面越長。
2. **評分 AI**：每次輸入很長（判斷卡＋整段對話），但次數少；開了提示快取會便宜很多。
3. **偵測 AI**：次數多，但每次只送增量，單次很便宜。

**建議做法**：先寫好評分的 system prompt，拿幾段模擬對話實際呼叫一次，看回傳的 token 用量，
再乘上預估的學生人數與使用次數。這樣比憑空估準確，也能順便驗證判斷卡寫得好不好。
測試時先設一個小的花費上限。
